feat(auth): Implementar sistema de asignaciones de usuario flexibles

Se refactoriza por completo el sistema de autenticación y permisos para pasar de un modelo de rol único por usuario a un sistema de asignaciones múltiples y flexibles.

**Cambios Arquitectónicos:**
- Se introduce la tabla `user_assignments` como única fuente de verdad para los permisos, permitiendo que un usuario tenga múltiples roles en diferentes tenants y sucursales.
- La tabla `users` se limpia para contener únicamente información de identidad.
- Todas las funciones de backend (RPCs) y políticas de seguridad (RLS) han sido refactorizadas para operar con el nuevo modelo de asignaciones.
- El `AuthContext` en el frontend se ha rediseñado para manejar un perfil de usuario y una lista de asignaciones, incluyendo un contexto de asignación activa.

**Nuevas Funcionalidades y Mejoras:**
- **Selector de Contexto:** Los usuarios con múltiples asignaciones ahora tienen un desplegable en el `Header` para cambiar de contexto (tenant/rol) dinámicamente.
- **Filtro de Sucursal Global:** El rol `tenant_super_admin` ahora dispone de un filtro global en el `Header` para visualizar los datos de "Todas las Sucursales" o de una sucursal específica.
- **Unificación de UI:** Se ha unificado el formato de precios en toda la aplicación a través del hook `usePriceFormat`, que ahora respeta la jerarquía de configuración Usuario > Tenant. Se han unificado también los estilos de padding y los componentes de layout entre los portales de Superadmin y Tenant.

**Correcciones:**
- Se solucionan numerosos errores de login, redirección y carga de datos que surgieron de inconsistencias entre el frontend y el backend.
- Se refactorizan múltiples componentes y hooks para alinearlos con la nueva arquitectura, eliminando código duplicado y "quemado".

Este commit representa una mejora fundamental en la escalabilidad y robustez de la arquitectura de la aplicación.
