feat: Implementa arquitectura de Ventas, Inventario y Numeración

Este commit refactoriza la lógica central de ventas e inventario e introduce un sistema flexible de numeración de documentos.

Cambios clave:

- **Refactorización del Esquema de Base de Datos:**
  - Desacopla las ventas de las facturas introduciendo las tablas `sales` y `sales_items`.
  - Añade la tabla `product_movements` para un seguimiento de inventario robusto y auditable.
  - Implementa la tabla `document_sequences` para gestionar la numeración de todos los tipos de documentos, con soporte para secuencias por sucursal o para todo el tenant.

- **Revisión de la Lógica de Backend:**
  - Crea la función RPC `process_sale_from_attention` para orquestar todo el flujo de venta.
  - Implementa la función RPC `get_next_document_number` con un motor de plantillas (`{prefix}`, `{sequence}`, `{YYYY}`, etc.) y bloqueo de fila para evitar concurrencia.
  - Añade las funciones RPC `create_product_movement` y `get_stock_snapshot` para la lógica de inventario.
  - Actualiza la Edge Function `tenant-actions` para integrar todas las nuevas RPCs.

- **Implementación de Frontend:**
  - Crea una nueva pestaña "Numeración" en Configuración con un CRUD completo para gestionar las secuencias.
  - Implementa un constructor visual en el formulario de secuencias con botones de placeholders y vista previa en tiempo real.
  - Añade nuevas páginas para los Informes de Inventario (Stock a Fecha y Kardex).
  - Refactoriza el diálogo de recibo (`ReceiptDialog`) para que consuma los datos de la nueva tabla `sales` y renderice la jerarquía de combos.

- **Correcciones y Pulido:**
  - Corrige múltiples errores de sintaxis SQL en las migraciones.
  - Soluciona errores de renderizado en React (`React is not defined`).
  - Mejora la UI de los formularios con diálogos desplazables y mejores descripciones.
